# Class demo checklist

Use a test account with fictional details. This checklist records what to check; it does not claim the checks have passed.

## Before the presentation

- [ ] Open the website on a laptop and a phone.
- [ ] Check that headings, buttons and forms fit both screens.
- [ ] Create a test account and sign out, then sign in again.
- [ ] Open each dashboard tool and confirm its main button works.
- [ ] Save a small test change, refresh, and confirm it remains saved.
- [ ] Open a course playlist and check that it leads to the intended resource.
- [ ] Check that a student account cannot open admin-only pages.
- [ ] Keep private setup codes, passwords and real student records off the shared screen.

## Phone and keyboard checks

- [ ] Try a narrow phone screen and check for sideways scrolling.
- [ ] Open the keyboard while filling a form; confirm the field and submit button remain reachable.
- [ ] Use Tab and Shift+Tab to move through controls and confirm the focused control is visible.
- [ ] Activate buttons with the keyboard and check that menus or dialogs can be closed.
- [ ] Increase browser zoom to 200% and confirm text and actions remain usable.
- [ ] Enable the device's reduced-motion setting and check pages with animation.

Record failures as issues. Completing this checklist is a practical check, not a full accessibility audit.

## During the presentation

1. Explain which student problem the website helps solve.
2. Show the dashboard and one complete task from start to finish.
3. Show how the saved result appears after refreshing.
4. Explain that local test data is separate from the hosted database.
5. Describe placement tools as preparation and support, not a job guarantee.

## Record issues

For each problem, note the page, steps, expected result, actual result, browser and time. Remove personal details from screenshots before sharing them.
